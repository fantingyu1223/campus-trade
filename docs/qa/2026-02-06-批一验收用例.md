- 测试范围：批一·地基功能 —— F1 三类身份认证（P0）、F36 高校名单管理（P0）、F5 商品发布（P0）、F6 分类浏览/搜索/筛选/排序（P0）、F7 商品状态管理（P0）、F2 个人/商家主页（P0）、F10a 急出标签（P1）、F33 商家标识与区分展示（P0）。
- 依据文档：
  - PRD：`docs/prd/2026-02-06-校园二手平台完整PRD.md` §5.1/§5.2（F#-AC# 验收标准、§7.2 口径裁决）。
  - 接口契约：`docs/design/2026-02-06-技术选型与总体方案.md` §5.2 用户端 API（前缀 `/api/v1`）、§5.3 后台 API（前缀 `/admin/v1`）、§5.1 错误码表。
- 覆盖率口径：P0 功能 AC 逐条映射，覆盖率 100%；F10a（P1）同步覆盖。共 19 条 AC、30 条用例。

## 2. 公共约定与测试数据

- 错误码引用（契约 §5.1）：1001 未登录、1003 无权限、1004 未通过实名认证、1006 学校未开放、2002 商品已下架/已售、2003 急出超 3 件上限、2004 图片不合规、9001 参数校验失败。
- 测试账号：`stu_a`（本校学生·已认证）、`stu_b`（本校学生·已认证，作买家）、`teacher_a`（教职工·已认证）、`merchant_a`（认证商家）、`user_new`（未认证）、`admin_op`（运营后台账号）。
- 基础数据：分类含"教材/教辅"；词表含违禁品词「气枪」、违规词「加微信」；商品库预置 ≥3 本《高等数学（下）》不同价格/成色，其中 1 本已售。
- 断言风格：API 用例断言 HTTP 状态 + 业务 code + 关键字段；UI 用例断言页面可见元素与跳转。

## 3. 用例清单

### 3.1 F1 三类身份认证（P0）

| 用例编号 | 对应 AC | 优先级 | 类型 |
| --- | --- | --- | --- |
| Q1-F1-01 | F1-AC1 | P0 | API |
| Q1-F1-02 | F1-AC1（§7.2 第10条） | P0 | API |
| Q1-F1-03 | F1-AC2 | P0 | API |
| Q1-F1-04 | F1-AC2 | P0 | API |
| Q1-F1-05 | F1-AC2 | P0 | API |
| Q1-F1-06 | F1-AC3 | P0 | API+UI |

**Q1-F1-01 学生认证通过并获得完整权限**
- 前置条件：`user_new` 已微信登录、未认证；本校在高校名单内。
- 步骤：① POST `/auth/verify`，`type=student`、`school_id=本校`、`real_name`、`evidence[]`（学生证图）；② GET `/auth/verify/status` 轮询至 approved（或审核钩子直接置通过）；③ GET `/auth/me`。
- 预期结果：① 返回 `verify_id`、`status=pending`；② 状态变为 `approved`；③ `user.role=student`、`verified=true`、`school_id=本校`，且该账号可成功调用 POST `/products`（发布权限生效）。

**Q1-F1-02 教职工认证沿用学生规则（口径裁决 §7.2-10）**
- 前置条件：新账号未认证。
- 步骤：POST `/auth/verify`，`type=teacher`、本校 `school_id`、教职工卡 `evidence[]`；审核通过后 GET `/auth/me`，并尝试发布商品。
- 预期结果：认证通过，`role=teacher`、`verified=true`；发布、会话、交易权限与学生一致（POST `/products` 成功），无额外教职工专属拦截。

**Q1-F1-03 未认证发布商品被拦截**
- 前置条件：`user_new` 未认证。
- 步骤：POST `/products`，携带完整合法商品字段。
- 预期结果：HTTP 403（或契约约定状态），业务 code=**1004**；响应提示引导认证；不产生商品记录（GET `/products/mine` 为空）。

**Q1-F1-04 未认证发起会话被拦截**
- 前置条件：`user_new` 未认证；存在在售商品 P1。
- 步骤：从 P1 详情发起会话（POST 会话创建/发消息接口）。
- 预期结果：被拦截，code=1004，提示引导跳转认证页；会话列表无新会话。

**Q1-F1-05 未认证浏览不受影响**
- 前置条件：`user_new` 未认证。
- 步骤：GET `/products`（列表）、GET `/products/{id}`（详情）。
- 预期结果：均正常返回 200 与商品数据，无 1004 拦截。

**Q1-F1-06 非本校学号/邮箱认证提示"暂不支持"并展示申请入口**
- 前置条件：`user_new` 未认证；名单外学校 X 大学（`school_id` 不存在或 status≠active）。
- 步骤：① POST `/auth/verify`，`type=student`，填写 X 大学学号/校园邮箱；② 认证页 UI 查看提示。
- 预期结果：① 拦截，code=**1006**，message 含"该校暂不支持"；② UI 提示文案一致，并展示"申请加入"入口（跳转 F36 申请提交，联动 Q1-F36-02）。

### 3.2 F36 高校名单管理（P0）

| 用例编号 | 对应 AC | 优先级 | 类型 |
| --- | --- | --- | --- |
| Q1-F36-01 | F36-AC1 | P0 | API |
| Q1-F36-02 | F36-AC1 | P0 | API+UI |
| Q1-F36-03 | F36-AC2 | P0 | API |

**Q1-F36-01 首期认证页学校列表仅本校**
- 前置条件：后台名单仅本校为 active。
- 步骤：GET `/schools`（无 keyword）。
- 预期结果：`list` 仅含本校 1 条，`{id, name, city}` 字段完整。

**Q1-F36-02 名单外学校提示"暂不支持"且可提交加入申请**
- 前置条件：X 大学不在名单（或 status=pending）。
- 步骤：① GET `/schools?keyword=X大学`；② POST `/schools/join`，`school_id=X大学标识`、`evidence[]`；③ UI 认证页选择 X 大学。
- 预期结果：① 列表不含 active 的 X 大学；② 返回 `apply_id`、`status=pending`（重复提交按契约幂等/拦截）；③ UI 展示"暂不支持"提示与"申请加入"入口且可提交成功。

**Q1-F36-03 运营新增高校后认证页同步可见且该校可认证**
- 前置条件：`admin_op` 已登录后台；Y 大学域名未被占用。
- 步骤：① POST `/admin/v1/schools`，`name=Y大学`、`domain=y.edu.cn`；② GET `/schools?keyword=Y大学`；③ 新用户以 Y 大学 `school_id` 提交学生认证。
- 预期结果：① 返回 `school{id}`；② 用户端列表同步含 Y 大学；③ 认证可提交并通过（验证配置通道可用；首期不启用新增——测试后由运营将 Y 大学下架恢复基线）。

| 用例编号 | 对应 AC | 优先级 | 类型 |

| Q1-F5-06 | F5-AC3 | P0 | API |

**Q1-F5-01 已认证卖家完整字段发布成功**
- 前置条件：`stu_a` 已认证；分类"教材/教辅"存在。
- 步骤：POST `/products`，`title=高等数学（下）九成新`、`desc`、`price=15`、`category_id=教材`、`condition=九成新`（成色规范选项）、`images[]`（1 张实拍图，jpg）、`trade_point=东门自提`、交易方式=当面自提。
- 预期结果：返回 `product_id`、`status=on_sale`（或 `audit_pending` 后审核通过转 on_sale）；GET `/products/{id}` 字段与提交一致。

**Q1-F5-02 发布流程不超过 3 步（N7）**
- 前置条件：`stu_a` 已认证，进入发布入口。
- 步骤：UI 操作：拍照/上传 → 填写信息 → 确认发布。
- 预期结果：自进入发布到上架成功，页面步骤数 ≤3，无强制额外页面；发布成功 toast 且商品出现在"我的商品"。

**Q1-F5-03 未上传实拍图发布被拦截**
- 前置条件：`stu_a` 已认证。
- 步骤：POST `/products`，`images=[]`，其余字段完整。
- 预期结果：拦截，code=**2004**（或 9001 且 message 指向图片缺失）；提示"实拍图缺失"；无商品记录生成。

**Q1-F5-04 未选成色发布被拦截并逐项提示缺失字段**
- 前置条件：`stu_a` 已认证。
- 步骤：POST `/products`，缺 `condition`（可扩展批量缺失：同时缺成色与价格）。
- 预期结果：拦截，code=9001；响应 message/field 逐项指明缺失字段（成色[/价格]），而非笼统报错。

**Q1-F5-05 标题命中违禁品清单发布被拦截**
- 前置条件：违禁品词表含「气枪」。
- 步骤：POST `/products`，`title=二手气枪配件`，其余字段合法。
- 预期结果：硬拦截，提示违禁品违规原因（与 F22/N3 联动）；商品不入库（列表与我的商品均查无）。

**Q1-F5-06 描述命中违规词表发布被拦截并提示原因**
- 前置条件：违规词表含「加微信」。
- 步骤：POST `/products`，`desc=有意者加微信联系`，其余字段合法。
- 预期结果：拦截，提示命中违规词及位置（标题/描述），告知修改后重试；不产生商品记录。

### 3.4 F6 分类浏览、搜索、筛选与排序（P0）

| 用例编号 | 对应 AC | 优先级 | 类型 |
| --- | --- | --- | --- |

| Q1-F6-03 | F6-AC2 | P0 | API |

**Q1-F6-01 书名搜索+价格升序+成色筛选结果正确**
- 前置条件：商品库含 ≥3 本《高等数学（下）》：价格 10/15/20，成色分别九成/七成/全新，均为在售。
- 步骤：GET `/products?keyword=高等数学（下）&sort=price_asc&condition=九成新`（成色筛选参数以契约为准）。
- 预期结果：结果均为在售、标题匹配关键词、成色=九成新；多条时按价格严格升序；分页结构完整。

**Q1-F6-02 搜索结果默认不包含已售商品**
- 前置条件：存在已售商品《高等数学（下）》（status=sold）。
- 步骤：① GET `/products?keyword=高等数学（下）`（默认 `exclude_sold=1`）；② 显式 `exclude_sold=1` 再查。
- 预期结果：两次结果均不含该已售商品；详情页仍可直达（联动 Q1-F7-02）。

**Q1-F6-03 "个人闲置/认证商家"过滤及恢复**
- 前置条件：列表同时含 `merchant_a` 商品与 `stu_a` 个人闲置。
- 步骤：① GET `/products?role_filter=merchant`；② GET `/products?role_filter=student`（个人闲置）；③ 不带 role_filter 再查。
- 预期结果：① 仅商家商品；② 仅个人闲置（student/teacher）；③ 恢复全量；每条 `seller_role` 与实际一致。

### 3.5 F7 商品状态管理（P0）

**Q1-F7-01 标记已售并指定买家成功，退出搜索且买家获评价入口**
- 前置条件：`stu_a` 有在售商品 P2；`stu_b` 与 `stu_a` 存在关于 P2 的会话。
- 步骤：① POST `/products/{P2}/sold`，`buyer_id=stu_b`；② GET `/products?keyword=P2标题`；③ 以 `stu_b` 查看评价入口。
- 预期结果：① 返回 `order_id`（自动生成线下订单），P2 status=sold；② 搜索结果不含 P2；③ `stu_b` 对该订单可见评价入口（review_pending，联动 F17）。

**Q1-F7-02 已售商品详情保留并显示"已售出"**
- 前置条件：P2 已标记已售。
- 步骤：GET `/products/{P2}`。
- 预期结果：详情正常返回（非 2001/404），`status=sold`，含"已售出"标识字段；UI 详情页展示"已售出"角标。

**Q1-F7-03 已下架商品发起新咨询被拦截**
- 前置条件：`stu_a` 商品 P3 已 POST `/products/{P3}/offline`。
- 步骤：`stu_b` 从 P3 详情发起会话/发送消息。
- 预期结果：拦截，code=**2002**，提示商品已下架；不产生新会话。

**Q1-F7-04 标记已售未指定买家被拦截**
- 前置条件：`stu_a` 有在售商品 P4。
- 步骤：POST `/products/{P4}/sold`，**不传** `buyer_id`。
- 预期结果：拦截，code=**9001**，message 明确"必须指定买家"；P4 状态仍为 on_sale。

### 3.6 F10a 急出标签（P1）

| 用例编号 | 对应 AC | 优先级 | 类型 |

**Q1-F10a-01 第 4 件急出打标被拦截**
- 前置条件：`stu_a` 已有 3 件在架商品 `is_urgent=true`；另有在架商品 P5 未打标。
- 步骤：PUT `/products/{P5}` 置 `is_urgent=true`（或带 `is_urgent=true` 新发布第 4 件）。
- 预期结果：拦截，code=**2003**，提示急出上限 3 件；P5 `is_urgent` 仍为 false。

**Q1-F10a-02 急出商品售出后额度释放可再打标**
- 前置条件：同 Q1-F10a-01（3 件急出生效中）。
- 步骤：① 将其中 1 件急出商品标记已售（指定 `stu_b`）；② 再对 P5 打急出标。
- 预期结果：① 售出成功且该商品 `is_urgent` 额度释放；② P5 打标成功（`is_urgent=true`），同时在架急出数仍 ≤3。

**Q1-F10a-03 急出商品下架同样释放额度（口径裁决 §7.2-7）**
- 前置条件：3 件急出在架。
- 步骤：① POST `/products/{急出品}/offline`；② 对 P5 打急出标。
- 预期结果：下架后额度立即释放，P5 打标成功。

**Q1-F10a-04 商家商品不享受急出加权**
- 前置条件：`merchant_a` 有在架商品 P6。
- 步骤：① 商家对 P6 打急出标；② GET `/products?urgent_only=true` 及默认列表观察排序。
- 预期结果：打标被拦截或打标不生效（提示商家不支持急出加权）；`urgent_only` 结果不含 P6；P6 在列表中无急出加权排序提升。

## 4. 异常路径覆盖核对（任务强制项）
