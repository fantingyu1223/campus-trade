# 会议纪要：团队启动讨论会

- 日期：2026-02-06
- 召集人：CEO
- 与会角色：pm、architect、researcher、backend-dev、frontend-dev、qa、devops、doc-writer（8 岗全员）
- 形式：CEO 基于 `docs/agent-team.md` v1.0 第 3、4 节，向各角色并行派发征询（三问：岗位输入/输出/接口；流程遗漏与矛盾；一条最有价值的修订建议），汇总后逐条裁决
- 状态：已闭会，决议已落盘

## 一、各角色核心意见摘要

| 角色 | 输入→输出→接口（确认） | 指出的主要问题 | 建议 |
| --- | --- | --- | --- |
| PM | CEO 需求/纪要 → PRD → CEO 评审 → 架构师/QA | ①缺"PM 提问—CEO 向用户确认—答复回传"的澄清回路；②PRD 无冻结与变更管理 | PRD 评审后冻结，变更走 CEO 裁决+纪要+升版本 |
| 架构师 | PRD+评审意见+调研报告 → 设计/契约 → 前后端/QA | ①契约冻结前无多方评审环节；②变更后同步机制缺失；③"新增接口须同步契约"与"冻结"存在张力 | 冻结前开契约评审会；冻结后变更版本化并通知 |
| 调研员 | CEO 自包含委派 → 调研报告 → CEO | 报告只在返回消息中，随会话蒸发无法回溯；缺受理回执与任务分级 | 报告默认落盘 `docs/research/` |
| 后端开发 | 冻结契约+CEO 委派 → 代码+交接 → CEO/QA | ①契约文档修改责任不清（我改还是架构师改）；②阻塞后任务挂起/恢复未定义 | 契约只能架构师改，开发只提不动 |
| 前端开发 | PRD 页面清单+冻结契约+Mock → 代码+交接 → CEO/QA | ①契约偏离后前端 Mock 无人通知；②"交互闭环"验收偏软；③兼任脚手架时组件库选型无归属 | 契约偏离显式标注、CEO 当天同步契约并通知对端 |
| QA | PRD 验收标准+契约+开发交接 → 用例/缺陷/结论 → CEO | ①缺陷无台账与状态流转，Blocker 门禁不可核查；②回归范围未界定；③测试环境无归属；④P0 覆盖率口径不明 | 建立 `docs/qa/defects/` 缺陷单规范 |
| DevOps | 技术栈约定 → 脚手架/CI/部署 → 前后端/QA/CEO | ①流程矛盾：DevOps 被排在开发阶段，但脚手架是开发前置依赖；②密钥只禁未管；③运维文档无目录 | 新增 `docs/ops/`；脚手架前置到契约冻结后 |
| 文档员 | 契约+代码+QA 报告 → 手册/索引 → CEO/使用者 | ①产出无目录归属；②工作流无文档员节点，易变"交付后补文档"；③契约变更不同步手册 | 新增 `docs/manual/`；变更当天同步手册 |

## 二、CEO 裁决结论

**采纳并落盘（已写入 `docs/agent-team.md` v1.1）：**

1. **基线冻结与变更管理（新 §3.4）**——PM、架构师、后端、前端四方意见合并：
   - PRD 评审后冻结，变更须 CEO 裁决 + 纪要 + PM 升版本；
   - 契约冻结前必经评审会（架构师+前后端+QA），纪要落盘；
   - 契约变更六步流程：上报→CEO 裁决→架构师改版→纪要→通知对端→文档员同步手册；
   - 契约文档只能架构师改，开发只提不动；实现偏离必须显式标注，静默偏离视为交付不合格。
2. **流程矛盾修正**：DevOps 脚手架前置到契约冻结后立即启动（§3.1/3.2/5 同步修正）；兼任脚手架时技术选型归属架构师（无设计时 CEO 裁决）。
3. **文档目录补齐**：新增 `docs/research/`（调研）、`docs/qa/defects/`（缺陷单台账，Blocker 清零以状态为准）、`docs/ops/`（运维）、`docs/manual/`（手册），索引入 `docs/README.md`。
4. **沟通机制补全（§4.3）**：澄清回路（问题清单→CEO 问用户→补充委派回传）；阻塞挂起与恢复（挂起标记→裁决后以自包含委派恢复并引用裁决结论）。
5. **验收标准细化**：前端"交互闭环"=主流程可用+空态/加载态/错误态齐备；QA 的 P0 覆盖率口径=PRD 验收条件逐条映射；回归默认影响面回归、交付前全量回归；测试环境由 DevOps 保障。
6. **运维规范补全**：密钥用 `.env.example` 模板+本地 `.env`（gitignore）；每次部署附回滚步骤。

**不采纳（附理由）：**

1. **调研员"受理回执机制"**：调研结论采纳/否决的反馈成本高、收益低，质量迭代已由每阶段复盘覆盖，不单设流程。
2. **调研员"任务分级标准"**：调研任务差异大，统一分级表难以适用；改为由 CEO 在委派验收标准中明确深度与时限（已并入 §2.3 交付物约定）。
3. **文档员"固定专人专职"**：维持兼任岗定位不变，但补上介入节点（交付前起草、复盘时定稿）解决"无人执行"问题。

## 三、最终确认的工作流程/协同/规范要点

- **六阶段工作流**：需求（PRD 冻结）→ 设计（契约评审会→契约冻结→DevOps 启动脚手架）→ 开发（前后端并行）→ 测试（缺陷台账，Blocker 清零方可交付）→ 交付（部署含回滚+文档员介入）→ 复盘（文档定稿）。
- **协同基石**：一切并行靠两份冻结基线（PRD、契约）解耦；一切变更走 CEO 裁决+纪要+版本化；一切交接自包含。
- **接口一览表**确认版见 `docs/agent-team.md` §3.5。
