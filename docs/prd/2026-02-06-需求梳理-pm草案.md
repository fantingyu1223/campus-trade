# 校园二手交易平台 · 需求梳理草案

- **版本**：v0.1
- **作者**：PM
- **日期**：2026-02-06
- **状态**：草案 - 待评审
- **说明**：本文档仅描述"做什么、要达到什么效果"，不涉及任何技术实现（不含技术栈、数据库、接口、架构等内容）。待 CEO 评审开放问题清单后，将基于决策结果细化为正式 PRD（含验收标准）。

## 1. 项目愿景与目标用户

### 1.1 愿景
让校园内每一件闲置物品都能安全、便捷地找到下一个主人，成为本校学生买卖闲置的首选入口。

### 1.2 目标用户
- **核心用户**：本校在校本科生、研究生（买卖双方均为学生）
- **次要用户**：本校教职工（是否开放待定，见开放问题）
- **运营角色**：平台运营/审核人员（负责内容审核、举报处理、风控）

### 1.3 要解决的痛点
| 痛点 | 现状 | 本平台目标 |
|---|---|---|
| 信息分散 | 交易信息散落在微信群、QQ群、朋友圈、宿舍楼公告栏，难搜难找 | 集中化信息平台，可搜索、可分类浏览 |
| 信任缺失 | 群里陌生人身份不明，付款/交货后跑路时有发生 | 校园实名认证 + 信用/评价体系 |
| 交易不规范 | 约定时间地点靠私聊，纠纷无法追溯 | 沟通记录、交易流程在平台内留痕 |
| 商品信息不真实 | 图文不符、成色虚报 | 强制实拍图与成色规范描述 |
| 黄牛与校外商家 | 专业贩子混迹校内群抬价倒卖 | 身份准入 + 行为识别 + 举报审核机制 |
| 毕业季供需错配 | 毕业生物品急于处理，低年级学生想捡漏但信息不通 | 毕业季专区/高效匹配 |

## 2. 典型使用场景与用户故事

### 2.1 核心业务闭环
**发布 → 浏览/搜索 → 沟通 → 交易（当面）→ 评价**

### 2.2 场景一：教材转让（最高频）
> 学期初，大二学生小 A 需要《高等数学（下）》教材。作为买家，小 A 希望搜索书名后按价格/成色筛选，看到实拍图确认无破损，联系卖家约好下午下课后在教学楼门口交接，当面验货付款，之后给卖家好评。

- 用户故事 US-01：作为**买家**，我希望按书名/课程名搜索教材，以便快速找到所需书籍。
- 用户故事 US-02：作为**买家**，我希望看到卖家的实名认证标识和历史评价，以便判断对方是否可信。

### 2.3 场景二：毕业季清仓（高峰）
> 大四学生小 B 六月初要离校，需要两周内处理掉台灯、自行车、小冰箱、一堆教材。小 B 希望批量快速发布，设置"毕业季急出"标签获得曝光，集中约买家在宿舍楼下自提。

- 用户故事 US-03：作为**卖家（毕业生）**，我希望发布流程极简（拍照→填标题/价格→发布），以便在短时间内上架多件物品。
- 用户故事 US-04：作为**卖家**，我希望物品售出后能快速标记"已售出"，避免重复被问。

### 2.4 场景三：求购（买方市场）
> 小 C 想买一台二手平板但平台上暂时没有合适的。小 C 发布求购信息（预期价位、成色要求），有卖家看到后可以主动联系小 C。

- 用户故事 US-05：作为**买家**，我希望发布求购需求，以便让潜在卖家主动找到我。

### 2.5 场景四：防诈骗与纠纷
> 小 D 在平台上看到一个远低于市价的手机，联系卖家后对方要求"先转账再发货"，小 D 警觉并通过举报按钮上报。运营审核后下架商品并封禁该账号。

- 用户故事 US-06：作为**买家**，我希望在沟通中得到防诈骗提示，并能一键举报可疑用户/商品。
- 用户故事 US-07：作为**运营人员**，我希望有举报处理队列和审核工具，以便及时处置违规内容与账号。

## 3. 功能需求清单（按业务模块分组，含优先级与取舍理由）

优先级定义：
- **P0**：没有它平台无法跑通核心闭环，首发必须有
- **P1**：显著提升体验或信任，首发或紧跟首发上线
- **P2**：锦上添花，冷启动稳定后再做

### 3.1 账号与身份
| # | 功能 | 优先级 | 取舍理由 |
|---|---|---|---|
| F1 | 校园实名认证（学号或校园邮箱验证） | **P0** | 校园平台信任基石，也是抑制校外商家的第一道闸门 |
| F2 | 个人主页（在售/已售商品、认证标识、评价展示） | **P0** | 买卖双方互相判断可信度的基础 |
| F3 | 头像/昵称/个人简介编辑 | **P1** | 影响体验但不阻塞交易闭环 |
| F4 | 信用分/等级体系 | **P2** | 需要交易数据积累，冷启动阶段意义有限 |

### 3.2 商品发布与浏览
| # | 功能 | 优先级 | 取舍理由 |
|---|---|---|---|
| F5 | 商品发布（标题、分类、成色、价格、实拍图、自提地点/可约时间、描述） | **P0** | 核心闭环起点 |
| F6 | 分类浏览与关键词搜索（按书名/课程名检索是教材场景刚需） | **P0** | 核心闭环必备 |
| F7 | 商品状态管理（上架/下架/标记已售） | **P0** | 无此功能将产生大量无效沟通 |
| F8 | 商品收藏/想要 | **P1** | 提升回访与撮合效率，非阻塞 |
| F9 | 求购专区 | **P1** | 校园教材/数码常有求大于供，显著提升撮合率，但可晚于发布端 |
| F10 | 毕业季专区/急出标签与集中曝光 | **P1** | 毕业季是全年最大供需高峰，运营价值高，但不阻塞日常闭环 |
| F11 | 商品视频、AI 识物、智能定价建议 | **P2** | 同类平台有，但成本高收益不确定，暂缓 |

### 3.3 沟通与交易
| # | 功能 | 优先级 | 取舍理由 |
|---|---|---|---|
| F12 | 站内即时沟通（买家问卖家） | **P0** | 交易约定（时间地点）依赖沟通，是闭环必备 |
| F13 | 防诈骗提示（聊天中检测"先款后货"等风险话术时警示；发布/聊天页常驻提示） | **P0** | 校园诈骗高发，属信任与安全底线 |
| F14 | 交易意向确认（双方确认约定的时间/地点，留痕） | **P1** | 减少爽约与扯皮，但早期可用聊天记录替代 |
| F15 | 消息通知（新留言、价格变动、求购匹配） | **P1** | 提升响应率，非闭环硬阻塞 |
| F16 | 砍价/报价工具 | **P2** | 聊天即可达成，形式化工具不急 |

### 3.4 信任与评价
| # | 功能 | 优先级 | 取舍理由 |
|---|---|---|---|
| F17 | 交易完成后的双方评价（文字+星级） | **P0** | 信任体系的最小闭环，没有它实名认证价值减半 |
| F18 | 举报（针对商品/用户/聊天） | **P0** | 平台自治与风控的入口，首发必须有 |
| F19 | 官方验机/鉴定服务 | **P2** | 重运营成本，早期不做 |

### 3.5 运营与治理
| # | 功能 | 优先级 | 取舍理由 |
|---|---|---|---|
| F20 | 举报处理队列（审核、处理、反馈给举报人） | **P0** | 举报无出口等于没有举报 |
| F21 | 商品/用户审核与处置（下架、警告、封禁） | **P0** | 治理能力的底线 |
| F22 | 违禁品/违规词识别与拦截 | **P1** | 早期人工审核可覆盖，量大后必须自动化 |
| F23 | 黄牛/商家行为识别（高频发布、多品类异常等特征预警） | **P1** | 抑制黄牛是校园平台特色诉求，需尽早积累数据 |
| F24 | 运营数据看板（发布量、成交量、举报率） | **P2** | 运营优化需要，首发可用简单统计替代 |

## 4. 非功能需求（校园场景特有，只描述要达到的效果）

| # | 需求 | 要达到的效果（衡量口径） |
|---|---|---|
| N1 | 身份真实性 | 平台注册用户必须能证明本校身份；未认证用户不可发布或发起交易（是否可浏览见开放问题） |
| N2 | 防诈骗有效性 | 用户在关键链路（聊天、约定交易）能看到防骗提示；平台对"先款后货"等典型话术具备警示能力；目标是诈骗类举报处理及时率 100%、重大诈骗事件 0 起 |
| N3 | 内容合规 | 违禁品（管制物品、考试作弊材料等）不得出现；违规内容在举报后有明确处置时限（如 24 小时内处理） |
| N4 | 毕业季高峰支撑 | 毕业季（5-7 月）发布量可达平时数倍，平台须在高峰期保持正常访问、发布、搜索不卡顿 |
| N5 | 信息真实性引导 | 商品必须含实拍图与规范成色选项；引导如实描述，虚假描述可被举报并影响信用 |
| N6 | 隐私保护 | 学号等实名信息对普通用户不可见，仅展示认证标识；聊天记录仅双方可见，纠纷仲裁时运营可调阅 |
| N7 | 易用性 | 学生能在 3 步内完成一件商品的发布；新用户 1 分钟内完成注册认证 |
| N8 | 交易安全兜底 | 平台不承担资金担保（若不做线上支付），但须提供清晰的交易安全指引与纠纷申诉通道 |

## 5. 明确暂不做的范围（Out of Scope）

| # | 不做的内容 | 理由 |
|---|---|---|
| O1 | 快递/物流配送 | 校园场景以当面自提为主，物流引入履约复杂度和售后纠纷，与"低成本轻运营"定位冲突 |
| O2 | 官方寄售/回收/验机服务 | 重资产重运营，早期团队不具备承接能力 |
| O3 | 跨校交易 | 信任半径与自提范围限于本校，跨校显著稀释"本校实名"的信任价值 |
| O4 | 社区社交功能（帖子、话题、动态） | 冷启动期内容分散注意力，先做交易工具再做社区 |
| O5 | 虚拟商品交易（游戏账号、充值卡等） | 诈骗重灾区，维权困难，风险远高于收益 |
| O6 | 拍卖/竞价模式 | 校园二手以一口价+议价为主，拍卖增加理解成本 |
| O7 | 多语言支持 | 本校学生为主要用户，无此需求 |
| O8 | 平台自营/介入定价 | 平台做中立撮合方，不定价、不兜底 |

## 6. 开放问题清单（需 CEO / 用户决策）

### Q1 是否支持线上支付，还是仅当面交易？
- 选项 A：仅当面交易（自提+线下付款/转账）
- 选项 B：线上支付+当面交货（付款走平台）
- 选项 C：线上支付+资金担保（确认收货后放款）
- **PM 建议：选项 A（首发），预留 B 的演进空间**。理由：当面自提是校园场景主流，不涉及资金即大幅降低诈骗风险与平台责任；资金担保（C）售后与纠纷处理成本极高，早期团队难以承接。

### Q2 是否仅限本校注册？
- 选项 A：仅限本校（学号/校园邮箱强校验）
- 选项 B：本校为主，开放少量同城高校
- 选项 C：完全开放
- **PM 建议：选项 A**。理由：本校实名是平台信任与防黄牛的核心资产，也是区别于闲鱼等泛平台的差异化；B/C 会显著增加审核与风控压力。

### Q3 产品形态：小程序还是 Web？
- 选项 A：小程序
- 选项 B：Web（响应式，兼容手机浏览器）
- 选项 C：小程序 + Web 双端
- **PM 建议：选项 A**。理由：学生使用场景高度移动化，小程序免安装、依托微信生态便于分享传播和消息触达，符合"毕业季快速铺开"的运营节奏；Web 可作为后续补充。

### Q4 是否允许校外人员/商家进入？
- 选项 A：完全禁止（仅本校认证用户可发布和交易）
- 选项 B：校外人员可浏览不可发布/交易
- 选项 C：允许认证商家入驻（收取费用或审核制）
- **PM 建议：选项 A**。理由：与 Q2 一致，抑制黄牛和商家是明确诉求；C 的商家化会破坏"同学间闲置流转"的社区氛围，且带来监管压力。

### Q5 商品品类是否设限？
- 选项 A：设正面清单（教材、数码、生活用品、服饰、运动器材等）+ 违禁品黑名单
- 选项 B：仅设黑名单（违禁品），其余开放
- 选项 C：不设限
- **PM 建议：选项 A**。理由：正面清单聚焦校园真实供需，利于分类导航与运营；黑名单单独明确违禁品（管制物品、作弊材料、虚拟商品等），边界清晰、审核有据。

### Q6 交易完成的判定与评价触发（关联闭环设计）
- 选项 A：买卖双方手动确认"交易完成"后互评
- 选项 B：卖家标记"已售出"并指定买家，买家可评价
- 选项 C：不做交易确认，仅允许对沟通过的用户评价
- **PM 建议：选项 B**。理由：当面交易无平台凭证，卖家标记已售是自然动作，据此绑定评价对象最简单且不易刷评价；A 的双确认容易一方不点导致评价链断裂。

### Q7 求购专区是否首发？（当前定为 P1）
- 选项 A：首发包含
- 选项 B：第二期上线
- **PM 建议：选项 B（跟随首发后 1 个月内）**。理由：冷启动期供给侧（发布）优先，求购在有一定用户基数后价值更大；但教材场景求购转化率高，不宜拖太久。

## 7. 关键取舍总结

1. **信任优先于功能丰富**：P0 集中在"实名认证 + 发布/搜索 + 沟通 + 评价 + 举报/审核"的最小信任闭环，砍掉了支付、物流、社区等重功能。
2. **校园特色做深**：毕业季专区、教材搜索、防诈骗提示、黄牛识别被列为 P0/P1，是与泛二手平台差异化的核心。
3. **轻运营起步**：不做担保、不做验机、不做物流，把运营资源集中在审核与举报处置上。
