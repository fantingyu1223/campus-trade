## 1. 阅读指南

- 每组旅程按**阶段**拆解，每阶段给出：用户目标 / 用户行为 / 触点·页面 / 痛点与情绪 / 对应功能编号。

- "对应功能编号"一列中出现 **缺口（G#）** 即表示该阶段需求清单未覆盖，详见第 6 节"旅程缺口检查"。

## 2. 买家旅程（全主流程）

> 人物：大二学生小 A，学期初买教材 + 日常淘闲置。

### 阶段 2.1 注册与认证

| 项 | 内容 |
|---|---|
| 用户目标 | 快速完成注册与实名认证，获得完整使用权限 |
| 用户行为 | 打开小程序 → 微信授权登录 → 选择身份（学生/教职工）→ 填写学号/校园邮箱完成认证 |
| 触点/页面 | 小程序首页、注册页、身份认证页、认证结果页 |
| 痛点与情绪 | 担心学号等隐私泄露（期待：N6 仅展示身份标识）；认证步骤多会流失（期待：N7 注册+认证 1 分钟内完成）；同城高校学生不确定自己的学校是否支持（缺口 G2） |
| 功能编号 | F1、N1、N6、N7；缺口 G2 |

### 阶段 2.2 浏览与搜索

| 项 | 内容 |
|---|---|
| 用户目标 | 快速找到目标商品，判断商品与卖家的可信度 |
| 用户行为 | 按分类浏览 / 搜索书名·课程名 → 按价格、成色筛选排序 → 按"个人闲置/认证商家"过滤 → 进入详情页查看实拍图、成色、自提地点 → 查看卖家主页（身份标识、学校、历史评价）→ 收藏心仪商品；搜不到时转求购专区发布求购 |
| 触点/页面 | 首页（分类入口、搜索框）、搜索结果页（筛选/排序/身份过滤）、商品详情页（实拍图、安全提示条）、卖家主页、求购专区 |
| 痛点与情绪 | 图文不符、成色虚报的担忧（N5 实拍图+规范成色）；分不清商家与个人（F33 强制标识）；搜不到的失落感（F9 求购兜底） |
| 功能编号 | F6、F2、F33、F5（信息结构）、F8、F9、N5；求购到期/关闭规则缺口见 G5 |

### 阶段 2.3 沟通协商（含双模式选择）

| 项 | 内容 |
|---|---|
| 用户目标 | 确认商品细节、议价、与卖家协商交易方式（当面自提 / 线上支付）并约定时间地点 |
| 用户行为 | 从详情页发起会话 → 询问成色/瑕疵/能否便宜 → 协商交易方式 → 约定交接时间地点 → 接收/确认交易意向 |
| 触点/页面 | 会话页（常驻安全提示）、会话列表、交易意向确认卡片 |
| 痛点与情绪 | 对方要求"先转账"时的警觉（F13 风险话术警示）；约定靠口头容易扯皮（F14 意向确认留痕）；被骚扰的担忧（F29 拉黑）；消息回复不及时（F15 通知） |
| 功能编号 | F12、F13、F34（协商环节）、F14、F29、F15、F16（P2） |

### 阶段 2.4 交易执行 · 分支 A：当面自提

| 项 | 内容 |
|---|---|
| 用户目标 | 当面验货，满意后线下付款，交易完成 |
| 用户行为 | 按约定到交接地点 → 当面验货 → 满意后线下扫码/现金付款 → 卖家标记已售并指定自己为买家 → 获得评价入口 |
| 触点/页面 | 会话页（约定信息）、交接现场（线下）、商品详情页（"已售出"标识）、评价入口 |
| 痛点与情绪 | 验货不满意的尴尬与争执（当面拒绝后交易如何收场，需求未定义，缺口 G3）；线下付款无平台凭证、事后举证难（缺口 G4）；卖家错标买家导致拿不到评价入口（F30 救济）；同城跨校交接地点安全性（缺口 G6） |
| 功能编号 | F34、F7、F30（救济兜底）、N2、N8；缺口 G3、G4、G6 |

### 阶段 2.5 交易执行 · 分支 B：线上支付

| 项 | 内容 |
|---|---|
| 用户目标 | 平台内付款，当面验货无误后现场确认收货，交易完成 |
| 用户行为 | 协商确定线上支付 → 付款前阅读强制风险提示（"平台不托管资金，务必当面验货后再确认收货"）→ 平台内付款 → 约定当面交货 → 现场验货 → 满意则当场确认"已收货"→ 交易完成 |
| 触点/页面 | 付款页（强制风险提示弹层）、订单/交易状态页、交货现场确认收货按钮、评价入口 |
| 痛点与情绪 | "付款后卖家失联"的最大恐惧（N8 事前明示 + F30 事后申诉对冲，见边缘旅程 b）；验货不满意时能否现场拒收、已付款如何退回——需求未定义（缺口 G3，**最高风险**）；付款后到交货前反悔取消无规则（同 G3） |
| 功能编号 | F34、F13（支付链路强化提示）、N8、O10（边界）、F30；缺口 G3 |

### 阶段 2.6 评价与完成

| 项 | 内容 |
|---|---|
| 用户目标 | 对本次交易给出评价，沉淀信任记录 |
| 用户行为 | 交易完成后 7 天内撰写评价（文字+星级）→ 查看对方给自己的评价 → 逾期未评则默认好评 |
| 触点/页面 | 评价页、消息通知（评价提醒）、个人主页（评价展示） |
| 痛点与情绪 | 差评被报复的担忧；被错标已售/未被指定为买家时无评价入口（走 F30 申诉） |
| 功能编号 | F17、F15、F2、F30（Q6 救济） |

### 买家旅程 MOT（体验关键时刻）

1. **认证通过瞬间**：1 分钟内完成且隐私可控，决定新用户是否留下（N7/N6）。
2. **首次看到实拍图+卖家身份标识**：决定"这个平台信不信得过"（N5/F33）。
3. **线上支付付款前的风险提示弹层**：明示"不托管、当面验货再确认"，是平台免责与用户安全感共存的关键瞬间（F13/N8/O10）。
4. **当面验货那一刻**：满意→信任闭环；不满意→若无清晰退出路径（G3）将直接流失并产生负面口碑。
5. **诈骗举报被 4 小时内处理并收到结果通知**：决定用户是否相信平台治理能力（F20/N2）。

## 3. 卖家旅程（全主流程）

> 人物：大三学生小 E，出闲置数码与教材；毕业季变体见边缘旅程 d。

### 阶段 3.1 注册与认证

| 项 | 内容 |
|---|---|
| 用户目标 | 完成学生认证，获得发布权限 |
| 用户行为 | 同买家 2.1（身份选学生） |
| 触点/页面 | 注册页、认证页 |
| 痛点与情绪 | 同 2.1；毕业生关心认证有效期与毕业后账号处置（F27） |
| 功能编号 | F1、N1、N6、N7、F27；在途交易处置缺口见 G7 |

### 阶段 3.2 发布商品

| 项 | 内容 |
|---|---|
| 用户目标 | 3 步内完成一件商品上架，信息真实完整 |
| 用户行为 | 拍照（强制实拍图）→ 填标题/分类/成色（规范选项）/价格/描述 → 选自提地点与可约时间 → 选择支持的交易方式（当面自提/线上支付/两者皆可）→ 发布 → （可选）打"急出"标签 |
| 触点/页面 | 发布页（三步流程）、分类选择（正面清单）、发布成功页、我的商品列表 |
| 痛点与情绪 | 发布繁琐会放弃（N7 ≤3 步）；不确定品类能否发布（Q5 正面清单+违禁黑名单，F22 拦截）；定价比价无参考（F11 智能定价为 P2，暂缺） |
| 功能编号 | F5、F10a、F22、N5、N7、N3；急出防滥用缺口见 G8 |

### 阶段 3.3 响应咨询

| 项 | 内容 |
|---|---|
| 用户目标 | 及时回复买家问题，推进成交，同时不被骚扰 |
| 用户行为 | 接收新消息通知 → 会话中答疑、议价 → 协商交易方式与时间地点 → 确认交易意向 → 处理多人同时咨询 |
| 触点/页面 | 消息通知、会话列表、会话页、交易意向确认卡片 |
| 痛点与情绪 | 重复回答同样问题（F25 留言区为 P2，缓解有限）；一货多聊，成交后其他意向买家无感知（缺口 G9）；风险买家骚扰（F29 拉黑）；自己也收到防骗提示 |
| 功能编号 | F12、F15、F14、F13、F29、F25；缺口 G9 |

### 阶段 3.4 交易履约

| 项 | 内容 |
|---|---|
| 用户目标 | 按约定完成交接，顺利售出 |
| 用户行为 | **当面自提分支**：赴约 → 买家验货 → 收线下付款 → 标记已售并指定买家；**线上支付分支**：确认买家已付款 → 赴约交货 → 等买家现场确认收货 → 交易完成；爽约/验货不通过时重新上架 |
| 触点/页面 | 会话页、我的商品（状态管理）、标记已售弹窗（指定买家）、交易状态页 |
| 痛点与情绪 | 买家爽约无任何约束（需求未覆盖，缺口 G9 相关）；买家验货不满意/线上支付拒收时交易如何回退（缺口 G3）；错标买家引发申诉（F30） |
| 功能编号 | F34、F7、F30、N8；缺口 G3、G9 |

### 阶段 3.5 收款与评价

| 项 | 内容 |
|---|---|
| 用户目标 | 确认款项落袋、积累好评，处理可能的异议 |
| 用户行为 | 当面自提：线下收款即完成；线上支付：买家确认收货后交易完成收款 → 7 天内回评买家 → 若买家对交易结果申诉，配合运营调查；若被误处置可申诉 |
| 触点/页面 | 交易完成页、评价页、申诉/被申诉通知、个人主页 |
| 痛点与情绪 | 线上支付买家拖着不点"确认收货"（超时自动确认规则未定义，缺口 G3 子项）；差评影响后续出售（F17 差评申诉通道） |
| 功能编号 | F34、F17、F30、F31、F15；缺口 G3 |

### 卖家旅程 MOT

1. **第一件商品 3 步发布成功**：决定卖家是否继续发布其余闲置（N7）。
2. **第一笔成交并完成收款**：双模式下"钱货两讫"的确定性，是卖家口碑传播起点（F34）。
3. **标记已售指定买家的弹窗**：Q6 机制的核心触点，操作顺畅与否直接决定评价闭环与纠纷率（F7/F34）。
4. **被买家申诉/被差评时获得公正处理**：决定卖家对平台治理的信任（F30/F31/F17）。

## 4. 关键边缘旅程

### 4.a 买家被骗举报旅程

> 人物：小 G，发现远低于市价的手机，对方要求"先转账再发货"。

| 阶段 | 用户目标 | 用户行为 | 触点/页面 | 痛点与情绪 | 功能编号 |
|---|---|---|---|---|---|
| ① 察觉异常 | 识别风险、避免上当 | 会话中收到"先转账"话术 → 看到平台弹出的风险警示 → 决定不转账 | 会话页（风险警示弹层、常驻安全提示） | 警觉、后怕；若警示缺失则直接受骗 | F13、N2 |
| ② 一键举报 | 快速上报可疑对象 | 在会话/商品/用户主页点举报 → 选择类型（诈骗）→ 补充描述与截图 → 提交 | 举报入口（商品详情/会话/主页）、举报表单页 | 担心举报石沉大海、担心被对方报复（举报人保护未明示，缺口 G9 相关） | F18、N9 |
| ③ 运营处置 | 等待并获知处理结果 | 运营在诈骗类 4 小时时限内审核 → 下架商品、封禁账号 → 结果通知小 G | 运营审核后台（举报处理队列）、结果通知消息 | 等待焦虑；超时未处理会严重损害信任 | F20、F21、F15、N2 |
| ④ 后续保护 | 不再被该用户骚扰 | 拉黑对方；查看处置结果 | 会话页、用户主页 | 安全感恢复 | F29、F21 |

**MOT**：风险警示弹出的瞬间（决定钱是否被骗走）；4 小时内收到"已处理"通知的瞬间（决定用户是否向同学宣传"这个平台管事"）。

### 4.b 纠纷申诉旅程（含线上支付后卖家失联场景）

> 主场景：小 D 线上支付后，卖家失联不交货；变体：买家被错标为"已售买家"。

| 阶段 | 用户目标 | 用户行为 | 触点/页面 | 痛点与情绪 | 功能编号 |
|---|---|---|---|---|---|
| ① 异常发生 | 确认问题性质 | 线上付款后多次联系卖家无回应 / 超过约定时间未交货；或发现自己被错标已售 | 会话页（消息未读）、交易状态页 | 焦虑、愤怒；意识到平台不托管资金（事前已明示）时的无力感 | F34、N8、O10 |
| ② 发起申诉 | 找到明确的救济入口 | 从交易状态页/会话页进入申诉 → 选择申诉类型（卖家失联/错标已售/货不对板）→ 上传证据（聊天记录、付款凭证、约定信息）→ 提交 | 申诉入口、申诉表单页（证据上传） | 入口藏得深会加剧愤怒；证据项引导不清导致来回补充（申诉材料清单需明确，缺口 G3 相关） | F30、N9 |
| ③ 运营介入裁决 | 获得公正裁决 | 运营 48 小时内介入 → 调阅聊天/交易留痕（授权流程）→ 联系双方 → 裁决：协调退款/撤销错误标记/处置卖家账号（警告/封禁/撤销商家资质）→ 结果通知双方 | 运营仲裁后台、裁决结果通知 | 平台"可协调但无法强制退款"的边界若事前不知晓，此处是信任崩塌点（N8 事前明示至关重要）；等待 48 小时的焦虑（进度可见性未定义，缺口 G3 相关） | F30、F21、N6、N9、N8 |
| ④ 结果执行与救济 | 裁决落地、不服可再申诉 | 卖家被处置；买家获得退款协调结果；任一方对裁决不服在 7 天内申诉复核 | 处置通知、申诉复核入口 | 对"无法强制退款"的接受度取决于事前明示与过程透明 | F31、F30、F21 |

**MOT**：付款前看到"平台不托管、可协调不可强制退款"明示的瞬间（决定预期管理成败）；收到裁决结果的瞬间（决定用户是"认栽但理解"还是"卸载+负面传播"）。

### 4.c 商家入驻审核旅程（含被驳回分支）

> 人物：校内数码维修店经营者。

| 阶段 | 用户目标 | 用户行为 | 触点/页面 | 痛点与情绪 | 功能编号 |
|---|---|---|---|---|---|
| ① 申请入驻 | 以商家身份合规经营 | 注册 → 选择"商家"身份 → 填写门店信息 → 上传营业执照/校园门店证明 → 提交审核 | 注册页、商家入驻申请页（材料上传） | 材料要求不清楚导致反复补交（材料清单与示例需明示） | F1、F32、N6 |
| ② 等待审核 | 获知进度 | 等待运营人工审核 → 查看审核状态 | 审核状态页、消息通知 | 审核时限未定义→焦虑（**缺口 G9 子项**：F32 无 SLA）；进度不可见 | F32、F15；缺口 G9 |
| ③ 通过分支 | 开店经营 | 审核通过 → 获得"认证商家"标识 → 发布商品（强制亮标）→ 接单经营 | 审核通过通知、商家主页、发布页 | 荣誉感、信任背书 | F32、F33、F5 |
| ③' 驳回分支 | 知晓原因、整改再申请 | 审核驳回 → 收到驳回理由 → 补正材料 → 重新提交（再提交次数/冷却期未定义，缺口 G9 子项）；对驳回不服走申诉复核 | 驳回通知（含理由）、重新提交入口、申诉入口 | 无理由驳回会激怒商家；理由清晰+可再申请则转化为整改动力 | F32、F31、F15；缺口 G9 |
| ④ 持续合规 | 保住资质 | 遵守商家规则（不得以个人身份发布、亮标经营）；违规被处置（撤销资质）时可申诉 | 商家主页、违规处置通知、申诉入口 | 规则透明则安分经营 | F33、F21、F23、F31 |

**MOT**：提交材料后看到清晰审核时限与进度的瞬间（决定商家对平台专业度的第一印象）；驳回通知中理由是否具体可执行的瞬间（决定商家整改还是放弃）。

### 4.d 毕业季高峰旅程（毕业生批量清仓视角）

> 人物：大四学生小 B，六月初离校，两周内处理台灯、自行车、小冰箱、教材若干。

| 阶段 | 用户目标 | 用户行为 | 触点/页面 | 痛点与情绪 | 功能编号 |
|---|---|---|---|---|---|
| ① 批量上架 | 极短时间内上架多件物品 | 逐件拍照→填写→发布（3 步流程）；给急售物品打"急出"标签；分享到班级群/宿舍楼群 | 发布页、急出标签开关、小程序分享卡片 | 离校 deadline 压迫感强；逐件发布×N 件的重复劳动（**无批量/复制发布能力，缺口 G9 子项**）；高峰期操作变慢的担忧（N4） | F5、F10a、F28、N7、N4；缺口 G9 |
| ② 集中响应 | 高效处理大量咨询 | 同时回复多个买家会话；用交易意向确认锁定时间地点；集中在宿舍楼下安排交接时段 | 会话列表、消息通知、意向确认卡片 | 咨询爆炸、会话管理吃力；多个买家问同一件已口头答应别人的物品（缺口 G9） | F12、F15、F14；缺口 G9 |
| ③ 集中交接 | 按时段批量完成自提 | 与多个买家约定同一地点不同时段 → 逐笔验货收款 → 逐笔标记已售并指定买家 | 会话页、标记已售弹窗、商品状态列表 | 爽约率高（无约束机制，缺口 G9）；漏标/错标买家 | F34、F7；缺口 G9 |
| ④ 离校收尾 | 处理尾货与账号善后 | 未售出物品降价/下架/转赠；毕业后账号进入限期清仓期，逾期转只读或注销 | 我的商品（批量管理）、认证有效期提醒、账号设置 | 在途交易未完成时账号被限的担忧（**F27 与在途订单的衔接未定义，缺口 G7**） | F27、F7、F26；缺口 G7 |

**MOT**：两周 deadline 内"发布-咨询-交接"全链路是否顺畅（决定毕业生是"两周清仓成功"还是"东西全扔/寄回家"）；高峰期平台响应不卡顿（N4，决定高峰口碑）。

## 6. 旅程缺口检查（CEO 决策依据）

> 编号 G1-G9 中，实质缺口如下（G 编号与正文标注一一对应）。每条含：缺口描述 / 所在旅程阶段 / 建议功能定义 / 优先级建议。

| # | 缺口描述 | 所在旅程阶段 | 建议功能定义 | 优先级建议 |
|---|---|---|---|---|
| **G3**（最高风险） | **交易取消与拒收机制缺失**：线上支付后，买家验货不满意现场拒收、付款后交货前反悔、卖家不交货——三种情形下已付款如何退回、交易状态如何回退均无规则；买家确认收货亦无超时自动确认机制。F30 只覆盖"事后申诉"，缺少"事中退出"通道 | 2.4/2.5（买家交易分支）、3.4/3.5（卖家履约与收款）、4.b 申诉前置 | 新增功能：交易取消/拒收流程——买家付款后、确认收货前，任一方可发起取消（对方确认或超时默认同意），平台原路退回付款（平台不经手资金，仅发起原路退回指令）；买家确认收货设超时（如交货约定时间后 48 小时未确认且无异议则自动确认）；拒收须现场发起并留痕 | **P0**（双模式首发即暴露此问题，不解决则线上支付模式不可用） |
| **G2** | **同城高校范围未定**：Q2 开放"同城高校"，但支持哪些学校（认证白名单）未定义，同城学生在认证页可能找不到自己的学校 | 2.1/3.1 注册认证 | 新增运营配置项：同城高校名单（首期随正式 PRD 给出清单），认证页展示支持学校列表，名单外学校给出"暂不支持"提示 | **P0**（Q2 决策的执行前提） |

| **G6** | **跨校交接地点与安全指引缺失**：同城高校开放后，跨校交易的交接地点（校内？地铁站？）无引导，安全提示仍按"校内自提"语境设计 | 2.4、3.4、4.d | 扩展 F13 安全提示模板：增加跨校交接场景提示（建议选择双方学校内或公共场所、结伴前往）；发布页自提地点字段支持填写校外公共场所 | **P1**（Q2 决策配套） |
