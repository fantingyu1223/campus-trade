## 1. 项目愿景与目标用户

### 1.1 愿景
让校园内每一件闲置物品都能安全、便捷地找到下一个主人，成为本校学生买卖闲置的首选入口；运营稳定后扩展至同城高校。

### 1.2 目标用户
- **核心用户**：本校在校本科生、研究生（买卖双方均为学生）
- **扩展用户（MVP 后拓展）**：同城高校在校学生（凭本校学号/校园邮箱认证，名单管理见 F36；首期名单仅本校）、本校教职工
- **商家用户**：经资质审核的入驻商家（如校内书店、数码维修店等，见 F32/F33）
- **运营角色**：平台运营/审核人员（内容审核、举报处理、商家审核、风控）

### 1.3 要解决的痛点
| 痛点 | 现状 | 本平台目标 |
|---|---|---|
| 信息分散 | 交易信息散落在微信群、QQ群、朋友圈、宿舍楼公告栏 | 集中化信息平台，可搜索、可分类浏览 |
| 信任缺失 | 群里陌生人身份不明，付款/交货后跑路时有发生 | 实名认证（学生/商家分轨）+ 评价体系 |
| 交易不规范 | 约定时间地点靠私聊，纠纷无法追溯 | 沟通记录、交易流程在平台内留痕 |
| 商品信息不真实 | 图文不符、成色虚报 | 强制实拍图与成色规范描述 |
| 黄牛与伪装商家 | 职业卖家冒充学生混迹校内群抬价倒卖 | 身份分轨准入 + 商家强制亮标 + 行为识别 + 举报审核 |
| 支付方式单一 | 当面现金/转账不便，部分交易希望线上付款 | 当面自提与线上支付双模式并存（Q1 决策） |
| 毕业季供需错配 | 毕业生物品急于处理，低年级学生想捡漏但信息不通 | 急出标签/毕业季曝光、求购撮合 |

## 2. 典型使用场景与用户故事

### 2.1 核心业务闭环
**发布 → 浏览/搜索 → 沟通（协商交易方式）→ 交易（当面自提或线上支付）→ 评价**

### 2.2 场景一：教材转让（最高频）
> 学期初，大二学生小 A 需要《高等数学（下）》教材。小 A 搜索书名后按价格/成色筛选，看到实拍图确认无破损，联系卖家约好下午下课后在教学楼门口交接，当面验货付款，之后给卖家好评。

- US-01：作为**买家**，我希望按书名/课程名搜索教材并按价格/成色筛选排序，以便快速找到合适的书。
- US-02：作为**买家**，我希望看到卖家的身份标识（学生/教职工/认证商家）和历史评价，以便判断对方是否可信。

### 2.3 场景二：毕业季清仓（高峰）
> 大四学生小 B 六月初要离校，需两周内处理掉台灯、自行车、小冰箱和一堆教材。小 B 希望快速发布多件物品，打上"急出"标签获得曝光，集中约买家在宿舍楼下自提。

- US-03：作为**卖家（毕业生）**，我希望发布流程极简（拍照→填标题/价格→发布），以便短时间上架多件物品。
- US-04：作为**卖家**，我希望物品售出后能快速标记"已售出"并指定买家，避免重复被问，也让买家能评价我。

### 2.4 场景三：求购（买方市场，首发包含）
> 小 C 想买一台二手平板但平台上暂时没有合适的。小 C 发布求购信息（预期价位、成色要求），有卖家看到后主动联系小 C。

- US-05：作为**买家**，我希望发布求购需求，以便让潜在卖家主动找到我。

### 2.5 场景四：双模式交易
> 小 D 买一台二手显示器，与卖家协商后选择**线上支付**：小 D 在平台内完成付款，约定下午当面交货；当面验货无误后，小 D 在现场确认"已收货"，交易完成并互相评价。另一笔交易中，小 E 与卖家选择**当面自提**：验货后线下扫码转账，卖家标记已售。

- US-08：作为**买家**，我希望与卖家协商选择当面自提或线上支付，以便按商品价值和信任程度灵活决定。
- US-09：作为**买家**，我选择线上支付时，希望平台明确提示"平台不托管资金、务必当面验货后再确认收货"，以便我不被"付款后失联"诈骗。
- US-12：作为**买家**，验货不满意或付款后反悔时，我希望有明确的取消/拒收通道和退款规则，以便我能体面退出交易。

### 2.6 场景五：商家入驻与购物
> 校内数码维修店申请入驻，提交营业执照与门店证明，运营 2 个工作日内审核通过后获得"认证商家"标识开店。小 F 在商品列表中能一眼区分商家商品与同学闲置。

- US-10：作为**商家**，我希望提交资质证明入驻平台，合规经营并获得明确标识；被驳回时知道具体原因并可整改再申请。
- US-11：作为**买家**，我希望清楚区分商家商品与同学个人闲置，以便调整我的信任预期与议价方式。

### 2.7 场景六：防诈骗与纠纷
> 小 G 看到一个远低于市价的手机，对方要求"先转账再发货"。小 G 收到平台的风险警示，通过举报按钮上报。运营 4 小时内审核，下架商品并封禁该账号，处理结果通知小 G。

- US-06：作为**买家**，我希望沟通中出现风险话术时得到平台警示，并能一键举报可疑用户/商品，且举报身份对被举报方保密。
- US-07：作为**运营人员**，我希望有分级时限的举报处理队列和处置工具，以便及时处理违规内容与账号。

## 3. 功能需求清单（按业务模块分组，含优先级与取舍理由）

优先级定义：
- **P0**：没有它平台无法跑通核心闭环，首发必须有
- **P1**：显著提升体验或信任，首发或紧跟首发上线
- **P2**：锦上添花，冷启动稳定后再做

### 3.1 账号与身份
| # | 功能 | 优先级 | 取舍理由 |
|---|---|---|---|
| F1 | 三类身份认证：学生（学号/校园邮箱；**首期仅本校，同城高校支持 MVP 后启用**）、教职工、商家（资质材料） | **P0** | Q2/Q4 决策的直接落地；信任基石，身份分轨是商家治理的前提 |
| F36 | 高校名单管理：认证页展示支持学校列表；名单外学校提示"暂不支持"并可提交加入申请；**首期名单=本校单校，同城高校由运营在稳定后配置扩展** | **P0** | Q2 决策的执行框架（缺口 G2）；口径按 2026-02-06 排期决议收窄，功能不削减 |
| F32 | 商家入驻审核：提交营业执照/校园门店证明→运营人工审核→通过/驳回；**审核时限 2 个工作日（自材料提交完整起算）；驳回必须给出具体理由枚举；补正再申请不限次、每次驳回后 7 天冷却；审核进度对申请人可见** | **P0** | Q4 决策配套；SLA 规则由旅程验证补齐（缺口 G1） |

| F2 | 个人/商家主页（在售/已售商品、身份标识、学校、评价展示） | **P0** | 买卖双方互相判断可信度的基础 |
| F26 | 账号注销与资料删除 | **P0** | 隐私合规底线；注销后名下商品自动下架、会话保留期限明确 |
| F3 | 头像/昵称/个人简介编辑 | **P1** | 影响体验但不阻塞交易闭环 |
| F27 | 认证有效期与毕业处置：认证按学制有效；毕业后账号限期清仓，逾期转只读或注销；**前置校验——存在在途交易（已付款未确认/申诉中）或未结申诉时延后处置并通知用户限期完成，延后上限 30 天；在途交易不受身份状态变化影响直至完结** | **P1** | 堵住实名准入漏洞；在途衔接规则由旅程验证补齐（缺口 G7），须在首次毕业季（5 月）前上线 |
| F4 | 信用分/等级体系 | **P2** | 需交易数据积累，冷启动阶段意义有限 |

### 3.2 商品发布与浏览
| # | 功能 | 优先级 | 取舍理由 |
|---|---|---|---|
| F5 | 商品发布（标题、分类、成色、价格、实拍图、自提地点/可约时间、描述；发布时选择支持的交易方式：当面自提/线上支付/两者皆可） | **P0** | 核心闭环起点；交易方式选项为 Q1 决策配套 |

| F7 | 商品状态管理（上架/下架/标记已售）；已售商品默认不出现在搜索结果，详情页保留并显示"已售出"标识；下架商品不可被发起新咨询 | **P0** | 无此功能将产生大量无效沟通 |

| F10a | 急出标签：卖家可标记并获得列表加权曝光；**防滥用——每账号同时生效急出标签上限 3 件，商品售出自动释放额度；商家商品不享受急出加权** | **P1** | 轻量实现毕业季核心诉求；防滥用规则由旅程验证补齐（缺口 G8） |
| F28 | 商品/平台分享（小程序卡片转发给同学、群） | **P1** | 冷启动传播关键；Q3 已定小程序形态 |

| F11 | 商品视频、AI 识物、智能定价建议 | **P2** | 成本高收益不确定，同类验证为低优先级 |
| F25 | 商品留言区（公开提问，卖家公开回复） | **P2** | 轻互动，降低重复咨询；不做完整社区（见 O4） |

### 3.3 沟通与交易
| # | 功能 | 优先级 | 取舍理由 |
|---|---|---|---|
| F12 | 站内沟通：买家问卖家，含会话列表、消息已读/未读 | **P0** | 交易约定依赖沟通 |
| F13 | 防诈骗提示：命中风险词表时发送侧弹出警示（可继续发送但留痕）；聊天页与发布页常驻安全提示；**线上支付链路强化提示（"平台不托管资金，务必当面验货后再确认收货"）** | **P0** | 校园诈骗高发；双模式下线上支付链路是最高风险点 |
| F34 | 双模式交易流程：①沟通中协商交易方式（发布时的选择仅为意向声明，现场分歧以双方最终一致同意为准）；②当面自提：验货后线下付款，卖家标记已售并指定买家；③线上支付：买家平台内付款→约定当面交货→买家现场确认"已收货"→交易完成；**订单状态枚举：待交货/待确认/已完成/已取消/申诉中；线上支付付款成功后商品锁定为"交易中"，其他买家不可再付款（防超卖）**；全程留痕 | **P0** | Q1 决策落地核心；状态枚举与防超卖由 QA 终审补齐 |
| F35 | 交易取消/拒收与超时确认：**取消——买家付款后、确认收货前，任一方可发起取消，对方 24 小时未响应视为默认同意；退款原路退回，仅限"未确认收货"状态（平台不经手资金，仅发起原路退回）；拒收——当面验货不满意须现场发起并留痕（时间+说明）；超时确认——交货约定时间后 48 小时买家未确认且无异议，自动确认收货；取消成功后商品自动恢复上架（卖家可再下架）** | **P0** | 阻塞性缺口（G3）：线上支付模式无"事中退出"通道则不可上线 |
| F38 | 跨校交接安全提示与地点扩展：自提地点字段支持填写校外公共场所；地点为校外时向双方推送安全提示（建议选择双方学校内或公共场所、结伴前往） | **P1（顺延）** | 原 P0（缺口 G6）；2026-02-06 排期决议：首期仅本校、无跨校场景，降为 P1，同城高校开放时恢复 P0 并排入当期迭代 |
| F14 | 交易意向确认（双方确认约定的时间/地点，留痕） | **P1** | 减少爽约与扯皮，早期可用聊天记录替代 |
| F29 | 拉黑用户（拉黑后对方不可再发起会话） | **P1** | 防骚扰兜底 |
| F15 | 消息通知（新留言、价格变动、求购匹配、订单状态变更） | **P1** | 提升响应率；求购匹配随 F9 首发 |
| F37 | 当面自提双向交接确认：交易完成后双方在平台内互点"已完成交接"留痕；一方 48 小时未确认视为默认完成；可选上传付款截图凭证 | **P2** | 线下付款无平台凭证的补救（缺口 G4）；首发用聊天记录+标记已售留痕兜底 |
| F16 | 砍价/报价工具 | **P2** | 聊天即可达成，形式化工具不急 |

### 3.4 信任与评价
| # | 功能 | 优先级 | 取舍理由 |
|---|---|---|---|
| F17 | 交易评价（文字+星级）：交易完成后 7 天内可评，逾期默认好评（计入卖家评分与主页展示）；**评价延迟公开——双方均提交或评价期结束后统一公开，防报复性差评与骚扰**；差评可向运营申诉 | **P0** | 信任体系最小闭环；延迟公开防差评报复 |
| F18 | 举报（针对商品/用户/商家/聊天）；**举报人身份对被举报方不可见（匿名保护）** | **P0** | 平台自治与风控入口 |
| F30 | 纠纷申诉流程：买家对交易结果有异议（卖家失联/错标已售/货不对板）可申诉，运营 48 小时内介入裁决并通知双方；**线上支付纠纷平台可协调但无法强制退款，规则须事前明示** | **P1** | 双模式下买家救济通道；Q1 决策的风险兜底 |
| F31 | 被处理账号/商家申诉机制（误封可在 7 天内申诉，运营复核） | **P1** | 治理公正性兜底 |
| F39 | 爽约标记：交易意向确认后一方未赴约，另一方可标记"未赴约"，累计计入主页展示；被标记方可申诉撤销（防恶意互标）；暂不做惩罚性措施 | **P2** | 缺口 G9；早期用拉黑+差评消化，标记数据供复盘 |
| F19 | 官方验机/鉴定服务 | **P2** | 重运营成本，早期不做 |

### 3.5 运营与治理
| # | 功能 | 优先级 | 取舍理由 |
|---|---|---|---|

## 5. 明确暂不做的范围（Out of Scope）

| # | 不做的内容 | 理由 |
|---|---|---|
| O1 | 快递/物流配送 | 校园以当面自提为主，物流引入履约复杂度和售后纠纷 |

## 6. 开放问题决策结果（2026-02-06 用户拍板，已生效）

> 决策记录详见 `docs/meeting/2026-02-06-需求决策记录.md`。以下为决策及由此确立的产品规则。

### Q1 交易方式 → **决策：A+B 双模式并存**
产品规则：
- 卖家发布商品时选择支持的交易方式（当面自提 / 线上支付 / 两者皆可，仅为意向声明）；买卖双方在沟通中最终协商确定，现场分歧以双方最终一致同意为准（F5/F34）。
- **线上支付规则**：买家平台内付款 → 商品锁定"交易中"（防超卖）→ 约定当面交货 → 买家验货后现场确认"已收货"（48 小时超时自动确认）→ 交易完成进入评价（F34/F35）。
- **退出通道**：未确认收货前任一方可发起取消/拒收，原路退回（F35）。
- **平台边界**：不托管资金、不担保（O10）；线上支付链路强制展示防骗提示（F13）；纠纷走 F30，平台可协调但无法强制退款——此规则在买家付款前明示。

### Q2 注册范围 → **决策：B 开放同城高校（2026-02-06 排期决议收窄落地：首期仅本校，同城开放顺延至运营稳定后）**
产品规则：
- 学生认证支持本校与同城高校（学号/校园邮箱），支持学校名单由 F36 管理；**首期名单=本校单校**，同城高校由运营在稳定后配置扩展；个人主页展示所在学校。
- 跨校交接安全提示（F38）降为 P1，同城开放时恢复 P0；信任半径定义为"同城高校实名圈"；跨城市不做（O3）。

### Q3 端形态 → **决策：A 小程序**
产品规则：首发仅小程序；分享（F28）与消息通知（F15）按小程序生态能力设计；Web 端后续视需求补充。（运营管理后台为 Web 端，属内部工具，不在本决策范围。）

### Q4 校外人员/商家 → **决策：C 允许商家入驻**
产品规则：
- 商家须经资质审核（F32，2 个工作日 SLA，驳回给具体理由，可整改再申请）。
- 商家全链路强制"认证商家"标识，与学生闲置明确区分（F33）；商品列表可按身份过滤（F6）。
- 商家不得以个人身份发布；发现伪装按黄牛规则处置并撤销资质（F21/F23）；商家售违禁品加重处置（F21）。
- 未认证的校外普通人员：仅可浏览（沿用 N1）。

### Q5 品类设限 → **决策：A 正面清单 + 违禁黑名单**
产品规则：正面清单（教材、数码、生活用品、服饰、运动器材等，首期清单随正式 PRD 给出）；违禁黑名单见 N3。

### Q6 交易完成判定 → **决策：B 卖家标记已售并指定买家**
产品规则：卖家标记已售时指定买家→买家获得评价入口；卖家错标时买家通过 F30 申诉救济；评价延迟公开防报复（F17）。

### Q7 求购专区 → **决策：A 首发包含**
产品规则：F9 为 P0 随首发上线，含完整生命周期规则（30 天有效期、可关闭/已买到、停止撮合）；求购撮合提示（F15）同步首发。

## 7. 关键取舍总结

1. **信任优先于功能丰富**：P0 集中于"身份分轨认证 + 发布/搜索 + 沟通 + 双模式交易 + 评价 + 举报/审核 + 隐私兜底"的最小信任闭环。
2. **校园特色做深**：教材搜索、急出标签、防诈骗提示、伪装商家识别、毕业处置是差异化核心。
3. **双模式但责任边界清晰**：交易方式灵活（Q1），平台不托管不担保（O10），但有完整"事中退出"通道（F35）与事后申诉（F30）对冲风险。
4. **商家开门但严格亮标**：允许商家入驻（Q4）扩大供给，用"资质审核 SLA+强制标识+行为风控+违禁品加重处置"四件套对冲风险。
5. **首期聚焦本校**：同城高校的能力框架（F36）建好但名单收窄，避免冷启动期供给被稀释；同城开放时 F38 恢复 P0。
6. **可验收性兜底**：所有 P0 均有明确规则口径（时限、触发条件、状态枚举），可直接转化为测试用例。
