## 2. 各阶段详表

### S0 需求阶段（已完成 ✅）
- 产出：需求讨论稿 v0.5、用户旅程 v1.0、运营策略 v2.0；Q1-Q7、缺口规则、排期三问全部决策。
- 复盘：本阶段复盘随 S1 结束时合并进行。

### S1 正式 PRD 与冻结（已完成 ✅，M1 达成 2026-02-06）
- 产出：完整版 PRD v1.0（冻结基线）；过程文档：正式 PRD v1.0（存档）、角色需求与用户旅程 v1.0、PM 草案若干。
- 复盘：S0+S1 合并复盘待 CEO 安排（建议 S2 契约冻结后一并进行）。

### S2 设计（**当前阶段，进行中**）
- **目标**：技术方案与接口契约冻结，开发可并行开工。
- **主要任务**：架构师产出技术选型与总体方案（技术选型、模块划分、数据模型、API 契约草案、关键风险对策）；CEO 评审；契约评审会（架构师+前后端+QA）；契约冻结；**DevOps 随即启动脚手架**。
- **负责角色**：架构师主笔，调研员按需支撑，DevOps 脚手架，CEO 主持评审。
- **入口条件**：✅ 已满足（PRD 冻结）。
- **出口标准**：契约评审会纪要落盘、契约冻结、脚手架按文档可跑通（DevOps 验收标准）。
- **预估节奏**：1–2 个工作周期（约 2–4 天）。
- **注意**：本阶段起涉及技术内容；技术选型决策全部记入会议纪要；**关键风险前置核实：个人主体小程序无法接入微信支付（影响 F34 线上支付模式），架构师须给出对策**。

### S3 MVP 开发（P0 分三批）
- **目标**：交付全部 P0 功能（冻结基线口径：P0 共 18 项；F38 降 P1 后首批施工范围按批次划分执行）。
- **批次划分**（按依赖与业务闭环排序）：
  - **批 1 地基**：F1/F36 三类认证与高校名单（首期仅本校）、F5 发布、F6 浏览搜索筛选、F2 主页、F7 状态管理 → 出口后"能挂能逛"；
  - **批 2 闭环**：F12 沟通、F34 双模式交易、F35 取消/拒收/超时确认、F9 求购、F17 评价 → 出口后"能聊能买能评"；
  - **批 3 治理**：F13 防诈骗提示、F18 举报、F20 举报队列、F21 审核处置、F32/F33 商家审核与标识、F26 注销 → 出口后"管得住"。
- **负责角色**：后端+前端并行（契约已冻结）；DevOps 保障 CI；CEO 逐批核实。
- **入口条件**：S2 出口达成。
- **出口标准**：每批构建通过、已有测试全绿、交接自包含；P0 功能与设计逐条对应。
- **预估节奏**：每批约 3–5 天，合计约 2–3 周（含返工余量）。

### S4 测试与验收
- **目标**：P0 可交付质量确认。
- **主要任务**：QA 用例设计（随 PRD 冻结即启动，与 S3 并行）→ 执行 → 缺陷单流转 → 回归；CEO 对照冻结 PRD 验收。
- **负责角色**：QA 主导，开发修复，CEO 验收裁决。
- **入口条件**：S3 批 1 交付。
- **出口标准**：P0 用例覆盖率 100%（验收条件逐条映射）、Blocker 缺陷单清零、QA 结论"通过"。
- **预估节奏**：约 1 周（与批 3 开发部分重叠）。

### S5 上线准备（**时间锚定：3 月中下旬**）
- **目标**：小程序对外可访问，上线即有货。
- **主要任务**：DevOps 部署与回滚清单；平台备案与合规（含与校方沟通——零成本但必须做）；运营者按策略 v2.0 预备种子供给（自有闲置+预约代挂名单）；首期高校名单配置（**仅本校**）。
- **负责角色**：DevOps 部署，CEO 合规与验收，用户（运营者）备供给。
- **入口条件**：S4 通过。
- **出口标准**：小程序可正常访问使用；回滚清单演练过；首批 ≥30 件商品已上架。
- **预估节奏**：约 3–5 天（备案类事项可能拉长，2 月底前启动）。

### S6 MVP 种子运营期（上线后第 0–8 周）
- **目标**：验证"论坛迁移"假设（唯一目标，不追求收入与规模）。
- **主要任务**：按策略 v2.0 §2 执行——代挂供给、避坑帖+喜报内容寄生引流、前 50 用户私域运营、首单护航；Excel 台账双周复盘。
- **负责角色**：用户（运营者）主导，CEO 双周复盘支持，DevOps 待命。
- **入口条件**：S5 出口达成。
- **出口标准**：第 8 周北极星达成——周成交 15–20 单、30 日回访率 ≥20%、累计实名 200–300 人、在售 150–200 件。
- **预估节奏**：8 周（未达标允许顺延 4 周）；按 3 月中下旬上线推算，种子期覆盖 4–5 月，**毕业季（5–6 月）落在种子期尾部，作为放大器**。

### S7 MVP 退出评估
- **目标**：用数据决定下一步。
- **主要任务**：CEO 组织复盘会，逐条核对退出条件（连续 4 周周成交 ≥20 单；回访率 ≥20%；诈骗类举报处理及时率 100% 且无重大纠纷；运营节奏可持续）；产出复盘文档与进/不进增长期的决策建议，交用户拍板。
- **负责角色**：CEO 主持，全员提供数据与问题清单。
- **入口条件**：S6 结束（含顺延）。
- **出口标准**：复盘文档落盘 `docs/review/`，用户做出进/不进决策。
- **预估节奏**：1 个复盘周期。

### S8 增长期
- **目标**：放大供给与品类，解冻后置议题。
- **主要任务**：策略 v2.0 §5 后置决策逐项拍板（商家定价、大使激励、推广位冻结、扩张指标、广告合规）；P1/P2 功能排期（含 F38 恢复 P0 与同城高校开放、F27 最迟 4 月底上线——若 S8 晚于 4 月，F27 须在增长期前的首个 P1 迭代提前排入）；商业化启用（B 端服务费）。
- **入口条件**：S7 用户拍板"进"。
- **出口标准/节奏**：届时按新一期规划定义。

## 3. 关键里程碑与硬约束

| 里程碑 | 内容 | 时间锚点 |

| M1 | PRD 冻结（S1 出口） | ✅ **已达成（2026-02-06）** |

| M3 | P0 全量开发完成（S3 出口） | 启动后约 3–4 周 |
| M4 | 上线（S5 出口） | **目标 3 月中下旬（用户拍板）** |
| M5 | 北极星达成（S6 第 8 周） | 上线后 8 周（约 5 月中下旬，蹭毕业季尾部） |
| M6 | MVP 退出评审（S7） | 上线后 8–12 周 |

**硬约束：**
1. **5 月毕业季前 F27（毕业处置+在途衔接）必须上线**——F27 为 P1，须在 4 月底前排入迭代（早于 S8，见 S8 说明）。
2. **开学教材季（2–3 月）赶不上**——用户已拍板确认（排期 Q1=A），执行"错过节点顺延"原则。
3. **首个可争取节点为 5–6 月毕业季**——3 月中下旬上线则种子期尾部覆盖毕业季，要求 S2–S5 不延期。
4. **运营者时间硬约束**：18 小时/周（用户已确认），S6 所有动作不得超此负荷。
5. **首期仅本校**：F36 名单内容为本校单校；F38 降 P1 顺延至同城开放（裁决留痕见纪要补充决议）。
6. **微信支付资质风险**（S2 新增）：个人主体小程序无法接入微信支付，直接影响 F34 线上支付模式的落地形态；架构师须在技术方案中核实并给出对策，必要时提请用户决策。
